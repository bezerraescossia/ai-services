# Shared Data Model: Corrective RAG

**Epic**: .spec/01-corrective-rag/epic.md

Entities defined here are binding for every feature under this epic — a feature's own `data-model.md` (generated by `sdd-implement`'s Plan sub-stage) must reference these, not redefine them.

## Document Chunk

**Represents**: A unit of the indexed corpus produced by ingestion — the atomic thing retrieval returns and the evaluator scores.
**Used by**: DP1, DP2, MOD1, MOD2, EVAL1

| Field | Type | Notes |
|---|---|---|
| chunk_id | string | Stable identifier, unique within a corpus version |
| corpus_version | string | DVC-tracked data version this chunk belongs to (Principle I) |
| source_document_id | string | Identifier of the originating document |
| text | string | Chunk content |
| pii_flagged | boolean | Set by DP2's scrubbing pass; `true` blocks the chunk from indexing until resolved |
| embedding_ref | string | Pointer to the chunk's vector in the index, not the raw vector itself |
| retrievable | boolean | `false` by default when DP1 writes the chunk (unpublished); DP2 flips it to `true` once cleared, or leaves it `false`/quarantined if `pii_flagged` is `true`. MOD1's retriever MUST only query chunks where `retrievable=true` |

**Relationships**: Referenced by a Retrieval Decision Record's `retrieved_chunk_ids` and by an Eval Example's `relevance_labels`.

## Retrieval Decision Record

**Represents**: The auditable record of one query's full corrective-RAG decision — what was retrieved, how the evaluator scored it, whether fallback fired, and what was ultimately served. This is the core object CRAG adds on top of vanilla RAG.
**Used by**: MOD2, MOD3, MOD4, EVAL1, EVAL2, MON1, MON2

| Field | Type | Notes |
|---|---|---|
| decision_id | string | Unique identifier for this query's decision |
| query | string | User query (post-sanitization if it triggered fallback, per MOD5) |
| retrieved_chunk_ids | list[string] | Document Chunk IDs returned by MOD1's retriever |
| relevance_scores | list[float] | Per-chunk score from MOD2, same order as `retrieved_chunk_ids` |
| confidence_verdict | enum | `correct` / `ambiguous` / `incorrect`, MOD2's classification of overall retrieval |
| fallback_triggered | boolean | Whether MOD3's web-search fallback fired |
| fallback_source_ref | string \| null | Pointer to the fallback result used, if triggered |
| final_context_refs | list[string] | The chunks/fallback results actually passed to MOD4's generator |
| answer | string | MOD4's generated answer |
| routed_to_human | boolean | Set by DEPLOY3 when both evaluator and fallback are low-confidence |
| mlflow_run_id | string | Run this decision was logged under (Principle II) |

**Relationships**: References Document Chunk via `retrieved_chunk_ids` and `final_context_refs`.

## Eval Example

**Represents**: One labeled item in the held-out evaluation set — never used for training or prompt iteration (Principle III).
**Used by**: EVAL1, EVAL2, EVAL3

| Field | Type | Notes |
|---|---|---|
| example_id | string | Unique identifier |
| query | string | Held-out query |
| relevance_labels | map[chunk_id, label] | Gold relevance label per candidate Document Chunk |
| gold_answer | string | Reference answer used to score MOD4's output |
| requires_fallback | boolean | Gold label for whether this query should trigger MOD3 |
| demographic_slice | string \| null | Optional tag used by EVAL3's fairness/bias review to group results |

**Relationships**: `relevance_labels` keys reference Document Chunk; scored against a Retrieval Decision Record produced for the same `query`.
